# 테이블 레퍼런스 — customers · support_tickets · usage_monthly

다음에 이 테이블을 쓰는 Claude가 먼저 읽는 문서입니다. 숫자는 모두 SQL로 센 값입니다. 정의를 모르는 것은 «물을 것»에 남겼습니다.

## customers

| 항목 | 내용 |
|---|---|
| 그레인 | 고객 1명 = 1행 |
| 키 | customer_id (50,000행 = 고유 50,000, 결측 0) |
| 크기 | 50,000행 × 13컬럼 |
| 기간 | 가입일 2018-12-25 ~ 2025-12-31(85개월, 빠진 달 없음) · 이탈일 2025-01-01 ~ 2025-12-31(월 527~690건) |
| 조인 | 다른 두 테이블이 customer_id로 붙는 기준 테이블 (자신은 조인 걸음 해당 없음) |

**센 것**
- 이탈: is_churned true 7,256 / false 42,744. churn_date 결측 42,744 = false 행 수. 이탈 여부와 날짜는 서로 맞고, 날짜가 가입일보다 앞선 행은 0.
- 가입 연도별 이탈률은 2018~2024가 15.0~16.1%, 2025년 가입자만 8.2%(530/6,485).
- 가입 건수가 적은 달: 2024-12 25건, 2025-01 345건, 2025-02 401건 (앞뒤 달은 591건·650건).
- plan_type: LTE기본 13,781 / LTE무제한 12,404 / 5G스탠다드 10,953 / 알뜰 7,711 / 5G프리미엄 5,151.
- monthly_fee는 플랜마다 값이 하나: 알뜰 19,000 / LTE기본 33,000 / LTE무제한 45,000 / 5G스탠다드 55,000 / 5G프리미엄 89,000.
- acquisition_channel: 검색 17,416 / 디스플레이 11,571 / 제휴 9,516 / 추천 7,460 / 오프라인 4,037.
- age_group 5가지, device_os(Android 30,925 / iOS 19,075), region 17개 시도.

**쓰면 안 되는 컬럼과 이유**
- customer_name: 고유 22,742개, 같은 이름이 최대 9명. 식별자가 아님.
- visitor_id · campaign_id: 값이 있는 행이 각각 6,485개로 모두 2025년 가입자. 2018~2024년 가입자 43,515행은 NULL. 오프라인 채널에도 campaign_id가 557건 있음. 전체 고객 분석에는 쓰지 않고 2025년 가입자 한정 분석에만 씀.
- monthly_fee: plan_type에서 완전히 결정됨. 고객별 실제 청구액·매출로 해석하지 않음.
- is_churned · churn_date: 이탈일이 전부 2025년. 2024년 이전 이탈은 보이지 않을 수 있어 가입 연도 사이의 이탈률 비교는 관찰 기간을 맞춘 뒤에만.
- 2024-12 ~ 2025-02 가입 건수: 원인 확인 전에는 월 단위 추세에 쓰지 않음.

**데이터를 만든 사람에게 물을 것**
1. 2024-12(25건), 2025-01(345건), 2025-02(401건)가 적은 이유 — 적재 누락인가, 실제 사건인가?
2. visitor_id · campaign_id가 2025년 가입자에게만 있는 이유.
3. 오프라인 채널 557명에게 campaign_id가 붙은 이유, campaign_id의 정의.
4. is_churned가 «2025년 중 이탈»인가, 전체 기간 이탈인가? 2024년 이전 이탈 고객은 제외됐는가?
5. monthly_fee는 정가인가 실제 청구액인가? 할인·결합 요금은 어디에 있는가?
6. customer_name 중복은 동명이인인가, 중복 등록인가?

## support_tickets

| 항목 | 내용 |
|---|---|
| 그레인 | 문의 1건 = 1행 |
| 키 | ticket_id (32,789행 = 고유 32,789) · 외래키 customer_id → customers, agent_id → agents(120개, 고아 0) |
| 크기 | 32,789행 × 10컬럼 |
| 기간 | 2025-01-01 ~ 2025-12-31, 12개월 모두 있음. 월 2,539(2월) ~ 2,883(12월) |

**customers와의 조인**
- 카디널리티: 티켓 N : 고객 1. 티켓의 customer_id 고유 23,398명.
- customers에 없는 키 0개. customers에만 있는 고객(티켓 0건) 26,602명.
- customers에 LEFT JOIN 하면 **32,789행**(행 수 그대로).
- 고객 단위로 보려면 customer_id로 먼저 집계한 뒤 붙임. customers 기준으로 티켓을 붙이면 고객 행이 늘어남.

**센 것**
- 결측은 10개 컬럼 모두 0.
- contact_channel: 전화 14,324 / 챗봇 7,967 / 앱 6,865 / 이메일 3,633.
- ticket_category: 요금 10,166 / 품질 7,794 / 가입변경 6,220 / 기타 4,349 / 해지 4,260.
- status: 완료 29,772 / 진행중 2,002 / 보류 1,015. is_recontact: false 25,362 / true 7,427.
- duration_min 1~80, resolution_hours 0.2~97.1.
- 가입일 이전 문의 0건, 해지일 이후 문의 0건.

**쓰면 안 되는 컬럼과 이유**
- resolution_hours: 진행중 2,002건·보류 1,015건에도 값이 전부 있고 평균이 비슷함(13.9 · 14.1 · 완료 14.5시간). 상담 시간(분)보다 짧은 행도 68건. 정의 확인 전에는 평균 해결 시간을 내지 않음.
- is_recontact: 고객의 첫 티켓 23,398건 중 5,339건이 true. 정의를 신뢰할 수 없음.
- duration_min: 채널별 평균이 13.2~13.3분으로 같아 채널 비교에 쓸 수 없음.
- ticket_category = 해지: 해지 문의 4,260건 중 해지 고객은 349건뿐(3,911건, 91.8%는 미해지). 해지는 customers.is_churned로 봄.

**데이터를 만든 사람에게 물을 것**
1. resolution_hours는 무엇을 잰 값인가? 진행중·보류 건에 값이 있는 이유는?
2. duration_min은 통화·채팅 시간인가 처리 시간인가? 채널별 평균이 같은 이유, 해결 시간(분)이 이보다 짧은 68건.
3. is_recontact의 기준(며칠 이내, 같은 카테고리 등)과 첫 티켓에 true가 있는 이유.
4. ticket_category «해지»는 해지 요청인가 방어 상담인가?
5. 진행중·보류 건은 이후 갱신되는가? 스냅샷 시점은?

## usage_monthly

| 항목 | 내용 |
|---|---|
| 그레인 | 고객 × 월 = 1행 |
| 키 | (customer_id, year_month), 523,825행 = 고유 조합 523,825 |
| 크기 | 523,825행 × 9컬럼. 고유 고객 49,985명, 12개월 모두 있는 고객 37,630명 |
| 기간 | 2025-01 ~ 2025-12, 12개월 연속. 월 43,412(12월) ~ 43,845(1월) |

**customers와의 조인**
- 카디널리티: usage N : 고객 1. customers에 없는 키 0개.
- customers에만 있는 고객 15명(전원 해지, 사용 이력 없음).
- customers에 LEFT JOIN 하면 **523,825행**(행 수 그대로).
- customers 기준으로 붙이면 15명은 사용량이 NULL로 남음.

**센 것**
- 결측·빈 문자열 0. year_month는 'YYYY-MM' 문자열(길이 전부 7).
- data_gb 0.23~128.27 · voice_min 55~239 · sms_count 0~32 · billing_amount 10,450~100,480 · app_login_count 0~36(0인 행 131) · service_count 0~12(0인 행 47,425).
- is_active는 523,825행 전부 True.
- 해지 고객 7,256명 중 12월 행이 남은 사람 668명. 해지월 이후의 행은 0건. 가입월 이전 행은 0건.
- billing_amount가 customers.monthly_fee와 같은 행은 12,848건, 다른 행은 510,977건. 요금제 정가의 약 70~80% 수준.

**쓰면 안 되는 컬럼과 이유**
- is_active: 전부 True라 정보가 없음. 해지는 customers.is_churned · churn_date로 봄.
- service_count: 0인 행 9.05%가 모두 is_active=True이고 data_gb·billing과 연관이 없음. 의미를 알 때까지 쓰지 않음.
- billing_amount: monthly_fee와 같은 값으로 취급하지 않음(98%가 다름). 매출로 쓰려면 정의부터 확인.

**데이터를 만든 사람에게 물을 것**
1. is_active의 정의, 전부 True인 이유, 해지월 행도 True가 맞는가?
2. service_count는 무엇을 세는가? 0이 9%인 것은 정상인가?
3. billing_amount는 실청구액인가 할인 후 금액인가? monthly_fee보다 20~30% 낮은 이유.
4. 해지월 행은 부분 월인가? customers에만 있는 15명의 사용 이력이 없는 이유.
5. 기간이 2025년 한 해로 고정된 것이 의도된 범위인가?
6. app_login_count 0인 131행과 data_gb 최솟값 0.23(0이 없음)은 정상인가?

## 분석 전에 알아 둘 것
1. 세 테이블 모두 customer_id로 N : 1 조인이고 고아 키는 0이라, customers에 LEFT JOIN 해도 행이 늘지 않음(32,789 · 523,825행). 반대 방향(고객 기준으로 티켓·사용량을 붙임)은 행이 불어남.
2. 기간은 usage_monthly·support_tickets가 2025년 12개월이고, is_churned도 2025년 이탈만 담김. 가입 연도별 이탈률을 비교할 때는 관찰 기간을 맞출 것.
3. is_active(전부 True)와 monthly_fee(플랜 정가)는 활성·매출의 근거가 못 됨. 해지는 is_churned, 매출은 정의 확인 후.
4. support_tickets의 resolution_hours · is_recontact · duration_min, ticket_category 해지는 정의가 맞지 않으니 확인 전에는 지표로 쓰지 않음.
5. 2024-12 ~ 2025-02 가입 건수와 visitor_id · campaign_id(2025년 가입자만)는 적재·추적 범위부터 확인.
